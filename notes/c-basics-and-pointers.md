## 関数・基本文法について

| 質問 | 回答の要点・注意点 |
|---|---|
| `return` は必須か。 | `void` 関数は末尾の `return;` を省略できる。値を返す一般の関数は、戻り値を利用する経路で値を返す必要がある。値を返さず末尾に到達し、その戻り値を呼び出し元が使うと未定義動作になる。通常の `int main` はC99以降、末尾到達が `return 0;` 相当になる。 |
| `main` の終了ステータスは何に使うのか。 | 呼び出した環境へ終了結果を伝える。`0` は正常終了を表し、シェルやスクリプトが結果に応じて後続処理を判断できる。 |
| `int main(void)` の `void` は何か。 | 括弧内の `void` は「引数なし」。戻り値の型を `void` にする指定とは異なる。C17以前の宣言 `int f();` は引数の情報を指定しないため、「何個でも渡してよい」という意味ではない。C23では空の括弧も引数なしを表す。 |
| 疑似命令とは何か。必ず関数の外に書くのか。 | Cの `#include` や `#define` はプリプロセッサへの指示。すべてが関数外に限定されるわけではなく、`#define` は関数内にも書けるが、ブロックの終わりで自動的に無効にはならない。`stdio.h` などの標準ヘッダは関数などの宣言・定義の外で読み込む。 |

基本文法の確認資料：[WG14 C11公開ドラフト N1570](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf) の §5.1.2.2.3（`main` の終了）、§6.7.6.3（関数の宣言）、§6.9.1（戻り値）、§6.10（プリプロセッサ）、§7.1.2（標準ヘッダ）。空括弧の変更は [N3220（C23後の作業ドラフト）](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n3220.pdf) の §6.7.7.4 を参照。

## Cの規格について

**質問：C99はいつ発行されたのか。現在の最新規格は何か。**

C99（ISO/IEC 9899:1999）は1999年12月に発行された。2026年10月12日時点で最新の発行済み規格はC23（ISO/IEC 9899:2024）で、2024年10月に発行されている。規格の名称と発行年が一致しない場合があるため、使用する規格はコンパイラの設定と併せて確認する。[ISOのC99情報](https://www.iso.org/standard/29237.html)、[ISOのC23情報](https://committee.iso.org/standard/82075.html)、[WG14の規格一覧](https://www.open-std.org/jtc1/sc22/wg14/www/projects.html)

## 変数の寿命・文字列について

| 質問 | 回答の要点・注意点 |
|---|---|
| 関数内の `static int count;` を `main` から使えるか。 | `count` という名前は宣言したブロック内でしか使えないが、値はプログラム終了まで保持される。値だけが必要なら戻り値で受け取れる。 |
| 関数内の `static` は、呼び出し元ごとに別の値になるか。 | 同じ変数を共有する。呼び出し元ごとのカウンタが必要なら、呼び出し元で変数を保持し、そのアドレスを関数へ渡す方法がある。 |
| `scanf` で `&` を使うのはなぜか。 | `scanf("%d", &num)` は `int` の格納先を指すポインタを渡す。`num` を渡すと値のコピーになり、`%d` が要求する引数の型と一致せず未定義動作になる。 |
| `str` は型か。文字列入力ではなぜ `&` が不要か。 | `char str[32];` の `char` は型、`str` は配列の名前。Cに組み込みの `str` 型はない。配列は多くの式で先頭要素へのポインタに変換されるため、文字列入力に渡せる。32要素なら `scanf("%31s", str)` のように終端の `\0` の分を残し、入力の成否も確認する。 |
| 文字列を `=` で代入、`==` で比較できないのはなぜか。 | 配列自体は代入できない。`char str[] = "hello";` は初期化であり代入とは別。文字列の内容をコピーするには容量を確認して `strcpy` などを使う。配列がポインタに変換された状態での `==` はアドレスの比較なので、内容の比較には `strcmp` を使う。配列とポインタは別の型である。 |
| 細かく処理を書くCの方が、RubyやPythonよりミスが減るのか。 | 処理を細かく書くことだけでは安全性は保証されない。Cでは配列の範囲や文字列の終端、メモリの寿命なども自分で確認する必要がある。 |
| 未定義動作とは何か。コンパイルが通れば安全か。 | 規格が動作を保証しない状態。配列の範囲外アクセス、寿命が終わった対象へのアクセスなどが該当する。コンパイル成功や一度の正常実行だけでは正しさの根拠にならない。 |

確認資料：[N1570](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf) の §3.4.3（未定義動作）、§6.2.1・§6.2.4（スコープ・寿命）、§6.3.2.1（配列の変換）、§6.5.16（代入）、§7.21.6.2（入力）、§7.24（文字列処理）。

## ポインタについて

**質問：通常の変数もメモリの値を扱うのに、ポインタとは何が違うのか。教材の「2つのモード」とは何か。**

通常の変数 `a` はその値を直接扱う。ポインタ変数 `p` は対象を指すアドレスを保持し、式 `*p` で対象を間接的に扱う。「モード」は教材の説明上の比喩で、変数の型が切り替わるわけではない。

```c
int a = 10;
int b = 20;
int *p = &a;  /* p は a を指す */
*p = 15;      /* a の値が 15 になる */
p = &b;       /* p が指す対象を b に変える */
*p = 25;      /* b の値が 25 になる */
```

これは説明用の例。`p` への代入と `*p` への代入で、変わる対象が異なることを来週の実行で確認する。

**質問：ポインタなら、元の変数名を使わず、スコープの外から値を読み書きできるのか。**

関数に有効なポインタを渡せば、その関数から元の変数名が見えなくても対象へアクセスできる。名前のスコープが変わるわけではない。対象の寿命、型、アクセスできる範囲を守る必要があり、関数終了後の通常のローカル変数や解放済みメモリを使うことはできない。

**質問：`void *` は何のためにあるのか。**

オブジェクトの型を特定せずにポインタを受け渡すための型で、`malloc` や汎用的な処理に使われる。`void *` のまま値を間接参照できないため、適切な型のポインタへ変換して扱う。Cでは `void *` とオブジェクトへのポインタの変換に明示的なキャストは必須ではない。型を変換すれば任意の読み書きが安全になる、という意味でもない。

**質問：ポインタはバグを生むだけではないか。何に使うのか。**

呼び出し元の変数を更新する、配列の要素を関数で扱う、動的に確保したメモリを使う、といった用途がある。Cの引数はポインタも含めて値渡しであり、ポインタの値をコピーして渡すことで、指す先の変数を操作できる。「参照渡し」という表現だけで理解すると、引数そのものと指す先を混同しやすい。

仕組みの説明は整理したものの、必要性はまだ実感できていない。まず、呼び出し元の変数を更新する小さな関数を書き、ポインタを使わない場合と比較する。

確認資料：[教材のポインタの説明](https://9cguide.appspot.com/15-04.html)、[N1570](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf) の §6.3.2.3（ポインタの変換）、§6.5.2.2（関数呼び出し）、§6.5.3.2（アドレス・間接参照）。
